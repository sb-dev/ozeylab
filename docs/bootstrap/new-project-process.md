# New project bootstrap

1. Resolve the selected route, accepted assessment revision and agreed initial scope.
2. Create a small target workspace with README and research records.
3. Save its custom bootstrap plan under docs/research-logs/bootstrap.md.
4. Resolve material gaps. Research reusable tools, templates, code and relevant skills.
5. Execute the scoped stages. Add the operating-model and launch specifications and real starting deliverables.
6. Verify each claimed behaviour and hand over the exact GitHub revision.

Plan generation and stage execution are separate. The scaffold command only starts
this process. Each stage records inputs, work, outputs, dependencies, budget and
exit evidence. Reuse completed stages; reject inconsistent resume state.

Commercial work and funding through first payment/delivery belong in
`docs/commercial-launch-spec.md`. Noncommercial outcomes use `docs/launch-spec.md`.
The central case owns comparative decisions. The target owns execution contracts.

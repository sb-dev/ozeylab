# L1-05 — Plan community repair sessions

[All examples](../README.md) · [Exercise brief](brief.md)

Assess a useful noncommercial outcome without inventing revenue.

**Status: designed, not executed.** Expected outputs below are acceptance requirements, not recorded results.

## Start

Use the [shared run instructions](../RUNNING.md) in a disposable ozeylab checkout. The brief is supplied input; it is not evidence of demand.

```bash
node scripts/cli.ts create example-l1-05 --spec examples/level-1-community-repair/brief.md
```

## Exact prompt

```text
Read examples/RUNNING.md and examples/level-1-community-repair/brief.md. Follow their evidence, review and execution rules.

Use case-study-create for example-l1-05. Set the objective to noncommercial from the supplied brief. Compare the three organising routes and screen all six families. Assess volunteer capacity, access needs, setup and continuing costs, funding gaps and dependencies on competent repair work. Define a first useful outcome and an observation that would show whether it helped. Quantify savings only where evidence supports them. Use a launch specification for the operational outcome rather than a commercial revenue target. Recommend one route without selecting it.

Report actual output paths, checks performed, unresolved evidence and the next decision. Distinguish a producer self-check from independent review.
```

## Expected outputs

## Check the result

- Unpaid labour still consumes the stated capacity.
- Missing funding is not filled with invented donations.
- A useful first outcome is measurable without a revenue forecast.

Apply the shared verification rules as well. A structural pass does not establish demand, correct judgement or a successful launch.

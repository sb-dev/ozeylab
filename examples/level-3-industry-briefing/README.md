## Exact prompt

```text
Read examples/RUNNING.md and examples/level-3-industry-briefing/brief.md. Follow their evidence, review and execution rules.

Use project-bootstrap for example-l3-03 after the accepted-selection preparation below. Use the information profile. Define the audience, inclusion rules, claim checks, correction process and production budget. Research and write one dated sample issue using sources actually inspected. Separate source statements from operating implications. Build and open a local HTML export. Rehearse correcting one labelled test error without overwriting the original issued sample. Record source access limits and production time. Do not invent developments to fill the format. Apply the shared GitHub handover rule before claiming completion.

Report actual output paths, checks performed, unresolved evidence and the next decision. Distinguish a producer self-check from independent review.
```

## Expected outputs

Paths below are relative to the target repository unless a central record is named.

- production/editorial.md with research, review and correction steps
- Dated source records, sample issue and local HTML export
- A correction rehearsal and launch plan for the first paying reader

## Check the result

- Each material factual claim has an inspected source and precise locator.
- The export retains dates, links and uncertainty.
- The correction record identifies the affected claim and preserves the earlier issue.

Apply the shared verification rules as well. A structural pass does not establish demand, correct judgement or a successful launch.

## Next decision

Test whether the intended audience values the issue before committing to a publishing cadence.
